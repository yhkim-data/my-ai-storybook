# AI 동화책 만들기 도구: Claude Code 실행 지시서

> **쓰는 법**: 빈 폴더에 이 파일을 넣고, 그 폴더에서 Claude Code를 연 다음 아래 한 줄을 입력한다.
>
> `STORYBOOK_BUILD.md를 읽고 처음부터 끝까지 실행해. 중간에 묻지 말고 12장의 완료 조건을 모두 채울 때까지 스스로 검증하고 고쳐.`

> **시작 전에 한 번**: 보조 작업자 정의를 제자리로 옮긴다. 이 폴더에서 아래 명령을 실행한 뒤에 Claude Code를 연다.
>
> 윈도우(PowerShell): `New-Item -ItemType Directory -Force .claude\agents; Copy-Item agents-setup\*.md .claude\agents\`
>
> WSL, 맥, 리눅스: `mkdir -p .claude/agents && cp agents-setup/*.md .claude/agents/`

이 문서는 Claude Code에게 주는 작업 지시서다. 아래 내용을 처음부터 끝까지 수행한다.

## 1. 무엇을 만드는가

AI를 전혀 모르는 학생과 선생님이 **웹 브라우저만으로** 짧은 그림책을 만드는 도구.

- 설치, 서버, 회원가입이 없다. GitHub Pages 주소를 열면 바로 쓴다.
- 질문에 답하고 버튼을 누르면 이야기와 그림이 만들어지고, 화면에서 바로 고쳐서 PDF로 받는다.
- **만든 책의 권리는 만든 사람에게 있다.** 이 도구와 개발자는 결과물에 어떤 권리도 주장하지 않는다. 이 문장을 README와 앱 안 "권리 안내" 화면에 한국어와 영어로 넣는다.
- 이 도구의 존재 이유는 "쉬움"이다. 프롬프트를 직접 쓸 줄 아는 사람은 이미지 AI를 바로 쓰면 된다. 모든 설계 판단에서 "처음 보는 초등 고학년이 설명 없이 끝까지 갈 수 있는가"를 기준으로 삼는다.

## 2. 반드시 지킬 제약

### 2-1. AI 제공사 조건은 직접 확인하고 기록한다

이 문서에 적힌 모델 이름, 가격, 무료 한도는 **참고값**이다. 구현 전에 제공사의 **공식 문서**(가격, 사용 한도, 이용약관, 모델 목록 페이지)를 직접 열어 확인하고, 확인한 날짜와 주소를 `docs/PROVIDER_NOTES.md`에 한국어로 기록한다. 공식 문서와 이 문서가 다르면 공식 문서를 따른다.

2026-11-14 조사 시점의 참고값:

- Gemini API의 **이미지 생성 모델에는 무료 한도가 없다**는 보고가 여럿 있다. 결제를 연결한 키가 필요하다.
- Gemini API의 **글 생성 모델은 무료 한도가 있으나 작다**. 일반 Flash 계열은 하루 20회 안팎, 경량(Flash-Lite) 계열은 하루 500회 안팎으로 보고된다.
- Gemini API 약관은 **만 18세 이상**만 쓸 수 있다고 정한다. 18세 미만을 대상으로 하는 앱에 쓰는 것을 제한하는 조항이 과거 판에 있었으니, 현재 약관에 남아 있는지 확인해서 기록한다.

### 2-2. 위 조건에 맞춘 설계 결정

1. **쓰는 사람 각자가 자기 키를 넣는다.** 시작 화면의 "AI 연결하기"에서 누구나 자기 키를 붙여넣을 수 있다. 화면 구성은 아래와 같다.
   - 키를 받는 방법을 그림과 함께 3~4단계로 보여준다 (제공사 사이트로 가는 버튼 포함).
   - 붙여넣는 칸 하나와 "연결 확인" 버튼 하나. 확인 결과를 "연결됐어요" 또는 "키가 맞지 않아요. 다시 복사해 볼까요?"처럼 쉬운 말로 알려준다.
   - 글용 키와 그림용 키를 따로 넣을 수 있다. 하나만 넣으면 둘 다에 쓴다.
   - "지금은 건너뛰기"를 누르면 키 없이 진행한다 (글은 직접 쓰고 그림은 올리는 방식).
   - 제공사 약관의 나이 조건은 `docs/PROVIDER_NOTES.md`에서 확인한 내용 그대로 이 화면에 한 줄로 알린다.
2. **그림은 세 가지 방법을 모두 제공한다.** 키가 없어도 책을 끝까지 만들 수 있어야 한다.
   - **AI로 만들기**: 연결된 이미지 모델로 생성 (키 필요, 유료일 수 있음)
   - **내 그림 올리기**: 직접 그렸거나 다른 곳에서 만든 그림 파일을 올림 (무료, 항상 가능)
   - **그림 설명 복사**: 완성된 그림 설명 문장을 복사해 다른 AI 앱에 붙여넣고, 받은 그림을 올림
3. **글도 키 없이 쓸 수 있다.** "내가 직접 쓸게요"를 고르면 AI 호출 없이 쪽마다 글을 직접 입력한다.
4. **AI 연결부는 갈아끼울 수 있게 만든다.** 4장의 Provider 구조를 따른다. 공식 문서를 확인한 결과 무료이면서 약관상 문제없는 다른 제공사가 있으면 추가 구현하고 `docs/PROVIDER_NOTES.md`에 근거를 적는다. 확인하지 못한 제공사는 넣지 않는다.

### 2-3. 키와 개인정보

- 키는 **브라우저의 localStorage에만** 저장한다. 어떤 서버로도 보내지 않는다. 브라우저에서 AI 제공사로 직접 호출한다.
- 저장소, 커밋, 테스트 코드, 문서 어디에도 실제 키를 넣지 않는다.
- "AI 연결하기" 화면에 "이 기기에서 키 지우기" 버튼을 둔다. 여럿이 함께 쓰는 기기에서는 끝나고 키를 지우라는 안내를 같은 화면에 넣는다.
- 키를 넣은 뒤에는 화면에 끝 4자리만 보여준다.
- 이야기 입력 화면에 "진짜 이름, 주소, 전화번호는 쓰지 마세요"라는 안내를 넣는다. 무료 한도로 쓰면 입력 내용이 제공사의 서비스 개선에 쓰일 수 있다는 점을 선생님 안내서에 적는다.

### 2-4. 글꼴과 소재의 라이선스

- 글꼴은 **SIL Open Font License(OFL)** 로 배포되는 한글 지원 글꼴만 쓴다. 본문용, 제목용, 손글씨풍 합쳐 3~4종이면 충분하다.
- 글꼴 파일을 저장소에 넣고(외부 CDN 호출 금지), 각 글꼴의 라이선스 전문을 `public/fonts/` 아래에 함께 넣는다.
- 아이콘, 샘플 그림 등 모든 소재는 직접 만들거나(SVG) 라이선스가 명확한 것만 쓰고 `THIRD_PARTY_NOTICES.md`에 출처와 라이선스를 적는다.

### 2-5. 독자 설계

- 다른 서비스의 화면 구성, 문구, 이름, 그림, 코드를 가져오지 않는다.
- 아래 두 저장소는 "이런 종류의 도구가 있다"는 참고일 뿐이다. 라이선스를 확인하지 못했으므로 코드를 복사하지 않는다.
  - https://github.com/jiwonpark0065/SeochoAICollege_AIBook
  - https://github.com/the0807/Starlight-Studio-BackEnd
- 그림체 이름에 특정 작가, 회사, 작품 이름을 쓰지 않는다. "수채화", "크레용", "점토 인형", "색종이 오려 붙이기", "연필 스케치", "도트 그림"처럼 일반적인 기법 이름만 쓴다.

### 2-6. 어린이 안전과 AI 표시

- AI에 보내는 지시문에 다음을 고정한다: 어린이용 그림책, 폭력·공포·선정적 내용 금지, 실제 인물과 기존 캐릭터·상표 금지.
- 제공사의 안전 설정은 기본값보다 낮추지 않는다.
- AI가 거절하거나 차단한 경우, 화면에는 "이 내용으로는 만들 수 없어요. 다른 말로 바꿔 볼까요?" 수준의 쉬운 문장을 보여준다.
- AI로 만든 그림이 한 장이라도 있으면, 책 마지막 "만든 사람" 쪽에 "그림 일부는 AI(모델 이름)로 만들었습니다"를 자동으로 넣는다. 직접 올린 그림만 있는 책에는 넣지 않는다.

### 2-7. DI Lab 표기

이 도구는 DI Lab(Data Insight Lab, 데이터 인사이트랩)이 만든다. 아래 자리에 반드시 넣는다.

- 모든 화면 머리글 오른쪽에 "DI Lab" 글자 표시 (남색 바탕, 흰 글자, 둥근 사각형).
- 시작 화면과 꾸미기 화면 바닥글에 "만든 곳 DI Lab · Data Insight Lab".
- README 두 개의 맨 아래와 `LICENSE`의 저작권자 줄.
- 내보낸 책에는 넣지 않는다. 책은 만든 사람의 것이므로 도구 이름이나 DI Lab 표기를 책 안에 자동으로 넣지 않는다.
- DI Lab의 공식 로고 그림은 받지 못했으므로 글자로만 표시한다. 로고 그림을 지어내지 않는다.

## 3. 사용 흐름

한 화면에서는 한 가지 일만 한다. 위쪽에 진행 단계를 점으로 보여준다. 언제든 이전 단계로 돌아갈 수 있고, 작업은 자동 저장된다.

| 단계 | 화면 | 하는 일 | AI 호출 |
|---|---|---|---|
| 1 | 시작 | 언어 선택, 새 책 만들기, 이어 만들기, 파일 불러오기, 체험판 보기, AI 연결하기 | 연결 확인 1회 |
| 2 | 이야기 씨앗 | 읽을 사람 나이대, 주제(칩 선택 또는 직접 입력), 주인공 이름과 모습, 쪽수 | 없음 |
| 3 | 줄거리 | AI가 줄거리 3개를 제안하면 고르거나 고침. "내가 직접 쓸게요" 선택 가능 | 1회 |
| 4 | 쪽 나누기 | 쪽마다 글과 그림 설명을 한꺼번에 받음. 쪽별로 직접 수정 가능 | 1회 |
| 5 | 그림체 | 6가지 그림체 중 선택 (예시 그림은 직접 만든 SVG) | 없음 |
| 6 | 그림 | 쪽마다 "AI로 만들기", "내 그림 올리기", "그림 설명 복사" 중 선택 | 쪽당 1회 |
| 7 | 꾸미기 | 글상자 위치·크기·글꼴·색, 글 고치기, 배치 바꾸기, 쪽 순서, 표지 | 없음 |
| 8 | 완성 | 넘겨보기, PDF 받기, 그림 묶음 받기, 작업 파일 받기 | 없음 |

### 3-1. 꾸미기 화면 (가장 중요)

AI를 다시 부르지 않고 화면에서 바로 고친다. 이 화면의 모든 동작은 브라우저 안에서만 일어난다.

- 글을 누르면 그 자리에서 바로 고친다.
- 글상자를 끌어서 옮기고, 모서리를 끌어서 크기를 바꾼다. 쪽 가장자리와 가운데에 자석처럼 붙는다.
- 글꼴, 글자 크기, 색, 정렬, 글상자 배경(없음, 반투명 흰색, 말풍선)을 고른다.
- 배치 미리 정해둔 것 5가지: 그림 위 글 아래, 글 위 그림 아래, 그림 왼쪽 글 오른쪽, 글 왼쪽 그림 오른쪽, 그림 가득에 글상자 얹기.
- 쪽을 끌어서 순서를 바꾸고, 쪽을 더하거나 뺀다.
- 되돌리기와 다시 하기 (최소 30단계).
- 그림만 다시 만들고 싶으면 그 쪽에서 "이 그림만 다시 만들기"를 누른다. 다른 쪽은 건드리지 않는다.

### 3-2. 주인공 모습 유지

- 2단계에서 받은 주인공 설명을 "주인공 카드"(겉모습을 묘사한 고정 문장)로 정리해서 모든 그림 설명 앞에 붙인다.
- 연결된 이미지 모델이 참고 그림 입력을 지원하면, 첫 번째로 만든 그림을 이후 쪽의 참고 그림으로 넣는다. 지원 여부는 공식 문서로 확인한다.

### 3-3. 내보내기

- **PDF (화면용)**: 쪽 그대로.
- **PDF (인쇄용)**: 사방 3mm 재단 여백 포함, 300dpi 기준.
- **그림 묶음**: 쪽별 PNG를 zip으로.
- **작업 파일**: 나중에 이어서 고칠 수 있는 파일 하나(`.storybook.json`, 그림 포함).
- PDF는 각 쪽을 화면에서 그림으로 바꾼 뒤 PDF에 넣는 방식으로 만든다. 한글 글꼴이 깨지는 문제를 피하기 위해서다.
- 책 순서: 표지, 본문, "만든 사람" 쪽.

## 4. 구조

### 4-1. 기술

- Vite + React + TypeScript
- 상태 관리: Zustand
- 꾸미기 화면: HTML/CSS 기반 직접 구현 (무거운 캔버스 라이브러리는 꼭 필요할 때만)
- 저장: IndexedDB (그림 포함 작업 내용), localStorage (설정과 키)
- PDF: pdf-lib, 쪽을 그림으로 바꾸는 데 html-to-image
- 번역: `src/i18n/ko.json`, `src/i18n/en.json` 두 파일과 얇은 도우미 함수
- 검사: ESLint, TypeScript strict, Vitest, Playwright
- 배포: GitHub Actions로 GitHub Pages에 올림. Vite의 `base`는 저장소 이름에 맞춘다.
- Node 20 이상. 패키지 버전은 설치 시점의 안정판을 쓰고 `package-lock.json`을 커밋한다.

### 4-2. AI 연결부 (Provider)

```ts
interface TextProvider {
  id: string;
  suggestPlots(seed: StorySeed, lang: Lang): Promise<Plot[]>;        // 줄거리 3개
  splitIntoPages(plot: Plot, seed: StorySeed, lang: Lang): Promise<PageDraft[]>; // 쪽별 글 + 그림 설명
  testConnection(): Promise<ConnectionResult>;
}

interface ImageProvider {
  id: string;
  supportsReferenceImage: boolean;
  generate(req: ImageRequest): Promise<Blob>;
  testConnection(): Promise<ConnectionResult>;
}
```

구현체:

- `gemini-text`, `gemini-image`: 모델 이름은 설정 화면에서 바꿀 수 있게 하고, 기본값은 공식 문서 확인 결과로 정한다.
- `mock-text`, `mock-image`: 키 없이 동작한다. 저장소에 넣어 둔 예시 이야기와 직접 만든 SVG 그림을 돌려준다. 자동 검사와 "체험판 보기"에서 쓴다.
- 글 응답은 구조화된 JSON으로 받고, 형식이 어긋나면 한 번만 다시 요청한다.

### 4-3. AI 호출을 아끼는 규칙

- 책 한 권의 글 호출은 **2회**(줄거리 제안, 쪽 나누기)를 목표로 한다. 글 다듬기 같은 추가 호출은 사용자가 그 쪽에서 버튼을 눌렀을 때만 한다.
- 그림은 쪽당 1회. 전체를 한꺼번에 만드는 "모두 만들기"는 제공사 한도를 넘지 않게 간격을 둔다.
- 같은 입력의 결과는 저장해 두고 다시 부르지 않는다.
- 꾸미기 화면에서는 AI를 부르지 않는다.
- 한도 초과 응답을 받으면 "오늘 쓸 수 있는 횟수를 다 썼어요" 또는 "조금 뒤에 다시 해 볼게요"처럼 쉬운 말로 알리고, 다시 시도할 수 있는 시간을 보여준다.
- "AI 연결하기" 화면에 오늘 이 기기에서 쓴 호출 횟수를 보여준다.

## 5. 쉬움 기준

- 화면에 "프롬프트", "API", "토큰", "모델" 같은 말을 쓰지 않는다. "그림 설명", "AI 연결", "횟수"처럼 바꿔 쓴다. "AI 연결하기" 화면에서도 "키"라는 말 하나만 쓰고, "AI를 쓰려면 필요한 나만의 비밀번호 같은 것"이라고 한 줄로 풀어준다. 모델 이름을 바꾸는 칸은 "자세한 설정"을 눌러야 보이게 접어 둔다.

## 7. 작업 순서

각 단계가 끝날 때마다 8장의 검사를 돌리고, 통과하면 커밋한다.

1. **조사**: 2-1의 공식 문서 확인, `docs/PROVIDER_NOTES.md` 작성.
2. **뼈대**: 프로젝트 생성, 검사 도구 설정, 번역 구조, 글꼴 넣기, 빈 8단계 화면 이동.
3. **데이터와 저장**: 책 데이터 구조, 자동 저장, 작업 파일 내보내기와 불러오기.
4. **가짜 AI 연결부와 체험판**: `mock-*` 구현, 예시 책.
5. **1~6단계 화면**: 가짜 연결부로 끝까지 동작.
6. **꾸미기 화면**: 3-1 전체.
7. **내보내기**: PDF 두 종류, 그림 묶음.
8. **실제 AI 연결부**: `gemini-*` 구현, "AI 연결하기" 화면, 연결 확인, 한도 처리.
9. **다듬기**: 5장 기준 점검, 작은 화면 대응, 오류 문구.
10. **문서와 화면 사진**.
11. **올리기**: 9장.
12. **최종 점검과 보고**: 10장, 11장.

### 7-1. 모델 나눠 쓰기

이 작업은 가장 높은 모델(Fable)로 시작한다. 주 작업자는 전체를 지휘하고 어려운 부분만 직접 하며, 나머지는 `.claude/agents/`에 미리 정의된 보조 작업자에게 맡긴다. 보조 작업자는 각자 정해진 더 가벼운 모델로 돈다.

| 누가 | 모델 | 맡는 일 |
|---|---|---|
| 주 작업자 | Fable (시작한 모델) | 1단계 조사와 판단, 폴더 구조와 데이터 구조 설계, AI 연결부 설계, 꾸미기 화면의 핵심 동작(끌기, 크기 바꾸기, 자석 붙기, 되돌리기), PDF 내보내기, 보조 작업자가 두 번 실패한 문제, 단계별 최종 확인, 9장의 올리기 |
| `builder` | sonnet | 설계가 끝난 화면과 부품 구현, 그에 딸린 검사 코드, 번역 문구 채우기 |
| `writer` | sonnet | 6장의 문서(한국어 원본과 영어판), 화면 사진 찍는 스크립트 |
| `checker` | haiku | 검사 명령 실행과 실패 요약, 번역 빠짐 검사, 키 새는지 검사, 파일 이름 바꾸기 같은 단순 반복 작업 |

맡기는 규칙:

1. **맡기기 전에 설계를 끝낸다.** 주 작업자가 파일 경로, 함수와 자료의 모양, 따를 시안 파일, 완료 기준을 정한 뒤에 맡긴다. 보조 작업자는 이 대화를 모르는 상태로 시작하므로, 맡기는 글에 필요한 것을 모두 적는다. "STORYBOOK_BUILD.md의 몇 장을 읽어라"처럼 읽을 곳을 짚어 준다.
2. **한 번에 한 덩어리.** 화면 하나, 문서 한 묶음처럼 끝이 분명한 단위로 맡긴다. 서로 같은 파일을 건드리지 않는 일은 동시에 맡긴다. 예: 2~5단계 화면을 `builder` 여러 개에 나눠 주고, 같은 때에 `writer`가 문서를 쓴다.
3. **보고는 짧게 받는다.** 보조 작업자는 바꾼 파일 목록, 돌린 검사와 결과, 못 한 것만 10줄 안으로 보고한다. 긴 출력은 주 작업자에게 가져오지 않는다.
4. **검사는 `checker`에게 돌리게 하고, 주 작업자는 요약만 본다.** 실패하면 실패한 검사 이름과 핵심 오류 3줄 이내만 받는다.
5. **확인은 주 작업자가 한다.** 보조 작업자가 "됐다"고 해도, 단계가 끝날 때 8-1의 검사 결과를 `checker`에게서 받아 통과를 확인한 뒤에 커밋한다.
6. **같은 일을 보조 작업자가 두 번 실패하면 주 작업자가 직접 한다.** 세 번째로 다시 맡기지 않는다.
7. **작은 일은 맡기지 않는다.** 파일 한두 개를 몇 줄 고치는 일은 맡기는 비용이 더 크다. 주 작업자가 바로 한다.
8. **`builder`, `writer`, `checker`가 목록에 없으면** (사람이 `agents-setup/`을 `.claude/agents/`로 옮기지 않은 경우) 일반 보조 작업자를 부르면서 모델을 위 표대로 직접 지정하고, 맡기는 글 맨 앞에 `agents-setup/`의 해당 파일 내용을 붙여 넣는다.
9. **모델 이름이 통하지 않으면** 모델을 지정하지 않고(시작한 모델 그대로) 맡기거나 주 작업자가 직접 하고, 그 사실을 `docs/DECISIONS.ko.md`에 적는다. 이 때문에 작업을 멈추지 않는다.

`.claude/`와 `agents-setup/` 폴더는 `.gitignore`에 넣어 저장소에 올리지 않는다.

## 8. 스스로 검증하는 방법

### 8-1. 매 단계 돌리는 검사

```
npm run lint
npm run typecheck
npm run test        # Vitest
npm run e2e         # Playwright, 가짜 AI 연결부 사용
npm run build
```

하나라도 실패하면 원인을 고치고 **전부 다시** 돌린다. 모두 통과할 때까지 다음 단계로 가지 않는다. 검사를 지우거나 건너뛰게 만들어서 통과시키지 않는다.

### 8-2. 꼭 있어야 하는 검사

- **끝까지 가보기 (Playwright)**: 새 책 만들기부터 PDF 받기까지 가짜 연결부로 진행하고, 받은 PDF의 쪽수가 표지 + 본문 + 만든 사람 쪽과 같은지 확인한다. 한국어와 영어 화면 각각, 태블릿과 휴대폰 크기 각각.
- **키 없이 끝까지**: 글은 직접 쓰고 그림은 올리기만으로 책이 완성되는지.
- **꾸미기**: 글 고치기, 글상자 끌기, 배치 바꾸기, 되돌리기 후 상태가 맞는지. 이 과정에서 AI 호출이 0회인지.
- **이어 만들기**: 새로고침 후 작업이 그대로인지, 작업 파일을 내보냈다가 불러오면 같은 책인지.
- **번역 빠짐 검사**: `ko.json`과 `en.json`의 항목이 정확히 같은지, 화면에 번역 키가 그대로 드러나는 곳이 없는지.
- **쉬운 말 검사**: 학생용 화면 문구에 "프롬프트", "API", "토큰", "prompt", "token"이 없는지.
- **한도와 오류**: 가짜 연결부가 한도 초과, 차단, 연결 끊김을 흉내 내게 해서 안내 문구와 다시 시도가 동작하는지.
- **키 새는지 검사**: 저장소 전체에서 키처럼 보이는 문자열을 찾는 스크립트(`npm run check:secrets`). 실제 연결부가 제공사 주소 외의 곳으로 요청을 보내지 않는지.
- **AI 연결하기**: 키 넣기, 연결 확인 성공과 실패 안내, 건너뛰기, 키 지우기가 동작하는지. 넣은 키가 화면에 끝 4자리만 보이는지.
- **AI 표시**: AI 그림이 있으면 "만든 사람" 쪽에 문구가 있고, 올린 그림만 있으면 없는지.

### 8-3. 실제 AI 연결부

환경 변수에 키가 있으면(`GEMINI_API_KEY`) 실제 호출 검사를 1회 돌린다. 없으면 건너뛰고, 건너뛰었다는 사실을 최종 보고에 적는다. 키를 요청하려고 작업을 멈추지 않는다.

### 8-4. 막혔을 때

같은 문제를 5번 고쳐도 통과하지 못하면, 그 기능을 가장 단순한 형태로 줄여서 통과시키고 `docs/KNOWN_ISSUES.ko.md`에 무엇을 줄였는지 적은 뒤 계속 진행한다.

## 9. GitHub에 올리기

1. `gh auth status`로 로그인 상태를 확인한다. 로그인되어 있지 않으면 9장만 건너뛰고, 사람이 실행할 명령을 최종 보고에 순서대로 적는다.
2. 같은 이름의 저장소가 이미 있으면 덮어쓰지 않는다. 이름 뒤에 `-2`를 붙여 새로 만든다.
3. `gh repo create <저장소 이름> --public --source=. --push`
4. 저장소 설명과 주제(topics)를 넣는다: 한국어와 영어 한 줄 소개, `storybook`, `education`, `generative-ai`, `korean`, `picture-book`, `kids`.
5. GitHub Pages를 GitHub Actions 방식으로 켜고, 배포 작업이 끝날 때까지 기다린다(`gh run watch`).
6. 배포된 주소를 열어 응답이 정상이고 앱 이름이 화면에 있는지 확인한다. 실패하면 원인(대부분 `base` 경로)을 고치고 다시 올린다.
7. README 두 개에 "바로 써보기" 주소를 넣고 다시 올린다.
8. 강제 올리기(`--force`)를 쓰지 않는다. `.env`와 키를 커밋하지 않는다.

커밋은 7장의 단계마다 나누고, 커밋 제목은 한국어로 무엇을 했는지 한 줄로 쓴다.
